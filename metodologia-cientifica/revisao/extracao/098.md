## 2. Decisão na leitura completa

**Incluído — IN1 + IN2.** Estudo empírico primário que executa testes de 116 projetos JavaScript no GitHub Actions CI, classifica causas de *flakiness* ambiental (SO, Node.js, navegador) e propõe e avalia uma estratégia de contenção (`js-env-sanitizer`) cujo objetivo explícito é permitir que builds de CI continuem. Nenhum critério de exclusão se aplica (versão revisada por pares: ICST 2026).

## 4. Contexto

- **Origem:** código aberto (GitHub). Conjunto final de 116 projetos: 100 dos mais populares e 16 adicionais com testes entre navegadores (p3).
- **Linguagem:** JavaScript/Node.js; *frameworks* Jest, Mocha e Vitest, entre outros (p3).
- **Tipos de teste:** testes das suítes dos projetos, incluindo testes de navegador/ponta a ponta (Karma, Playwright, Cypress etc., p3).
- **Sistema de CI:** GitHub Actions, com matriz de SO (Ubuntu 24.04, macOS 14, Windows Server 2022) × Node.js 18/20/22 e navegadores pré-instalados (p3–p4).
- **Como a CI é tratada:** a CI é tanto o ambiente do experimento quanto o alvo da mitigação ("allowing CI builds to continue/succeed", p1).

## 5. Definição de teste intermitente adotada

- "Flaky tests are tests whose outcomes alternate between pass and fail without any changes to the code." (p1)
- Teste intermitente ambiental: "tests that fail in one environment but pass in others (with other variables in control, including code)" (p2). Os autores observam que essas falhas "may be consistently tied to a specific environment or occur intermittently" (p2).

## 6. Método e amostra

- **Seleção:** 245 projetos mais estrelados → 170 com testes/Node.js → 100 executáveis; mais 16 projetos de navegador (total de 116) (p3).
- **Execução:** cada projeto foi rodado em 9 configurações, cada uma repetida 10 vezes, num total de 90 execuções (p3).
- **Análise:** dois autores examinaram cada falha de forma independente; um terceiro resolveu divergências em 12 projetos (p4).
- **Avaliação da ferramenta:** 15 projetos candidatos → 7 avaliados (p8–p9).

## 7. Causas identificadas

Prevalência: 65 projetos dependentes de ambiente entre os 116 (39 no nível do projeto, 28 com testes ambientais), com 1.355 testes dependentes de ambiente (p4). Números da Tabela III (p5):

| Causa | Números | Pág. | Citação |
|---|---|---|---|
| Dependência de SO | 28 projetos (21 no nível do projeto, 7 no nível de teste); falhas no Windows em 22 de 26 projetos, macOS 8, Ubuntu 2 | p5 | "fail when run on a specific OS due to differences in file system behavior (e.g., case sensitivity in file paths), line endings, shell command compatibility, or platform-specific dependencies" |
| Versão do Node.js | 5 (Tabela III: 3 + 2); o texto cita 4 projetos | p5–p6 | "typically caused by breaking changes in the API, deprecated APIs, stricter error handling, or differences in built-in module implementations" |
| Navegador (inclui navegador × SO) | 17 na Tabela III (8 + 9); o texto diz 15; maioria no macOS (8 projetos) | p6 | "typically caused by differences in browser engine behaviour, missing binaries, or variations in how browser APIs behave across platforms" |
| Combinação SO × Node.js | 16 projetos (8 + 8); Windows 13, macOS 8, Ubuntu 5 | p7 | "a test may pass under most conditions but fail only on a specific OS with a particular version of Node.js" |
| Não ambiental (por exemplo, espera assíncrona e *timeout*) | 5 projetos | p4 | "intermittently fails with the error: Timeout - Async function did not complete within 10000ms" |

Exemplos (p5–p7): `;` e caminhos com `\` no Windows, `TZ=` inline, Firefox ausente no macOS, *glob* no `cmd.exe`.

## 8. Estratégias de mitigação

1. **`js-env-sanitizer`: pular e reportar testes conforme o ambiente (quarentena por anotação).**
   - **Descrição:** tags em *docblock* (`@skipOnOs`, `@skipOnNodeVersion`, `@enableOnBrowser` etc.) são avaliadas em tempo de execução. O teste é marcado como *skipped* e o motivo é registrado em log (p7–p8).
   - **Causas tratadas:** SO, Node.js e navegador.
   - **Status:** avaliada no estudo.
   - **Resultados:** "the initially failing tests have all been successfully quarantined and reported as skipped, allowing the CI build to continue without the known test failure" (p9). A verificação manual não encontrou falsos positivos nem falsos negativos (p9).
   - **Tempo de execução (Tabela V, p10):** em fabric.js caiu de 1020 s para 65 s. Em outros projetos subiu (por exemplo, preact de 68 s para 147 s e iptv de 31 s para 77 s), embora os autores afirmem "no significant difference" para a maioria (p9).
   - **Custos e *trade-offs*:** os testes são pulados, não corrigidos. As anotações são manuais e só cobrem Jest, Mocha e Vitest. A integração falhou em insomnia (monorepo) e mongoose (p8).
2. **Correções no código e na configuração.**
   - **Descrição:** usar `cross-env`, normalizar caminhos, declarar as versões de Node.js suportadas, evitar asserções sobre mensagens de erro exatas e instalar os binários dos navegadores na CI (p5–p6, p9).
   - **Causas tratadas:** SO, Node.js e navegador.
   - **Status:** apenas recomendada.
   - **Citação:** "making sure the right browser binaries are installed in CI and writing tests that work across different engines reduces surprises" (p9).

## 9. Limitações relatadas pelos autores

- Generalização limitada aos projetos populares selecionados (p9).
- Análise manual sujeita a viés, mitigada por dupla revisão (p9).
- As versões dos navegadores não puderam ser variadas, pois estão acopladas ao SO (p3).
- Seis projetos foram excluídos da avaliação por usarem *frameworks* não suportados, e outros dois por problemas de integração (p8).

## 10. Observações para a síntese

- É o único estudo deste lote que **avalia** uma estratégia de contenção dentro da CI, uma alternativa leve ao *rerun*.
- A definição inclui falhas **determinísticas por ambiente**, o que estende o conceito clássico de intermitência. Isso deve ser explicitado ao comparar com outros estudos.
- A CI multiplataforma (matriz de SO/runtime) aparece como gatilho de intermitência. O Windows concentra as falhas de SO.
- Há inconsistências numéricas internas (ver QA4); é preferível citar a Tabela III.
